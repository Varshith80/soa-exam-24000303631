# Solar Panel Inventory

Full-stack solar panel inventory management using React, Spring Boot, PostgreSQL,
and Eureka service discovery.

## Repository layout

- `frontend/` — React/Vite UI, Bootstrap styling, Nginx config, and frontend Dockerfile.
- `backend/` — Spring Boot REST API using base package `com.klef.soa.docker`,
  validation, Swagger UI, and backend Dockerfile.
- `backend/EurekaServer/` — Eureka discovery server and its Dockerfile.
- `docker-compose.yml` — PostgreSQL, Eureka, backend, and frontend services.
- `.github/workflows/docker-publish.yml` — builds and publishes the frontend and
  backend images to Docker Hub.

## Run the full application with Docker Compose

Install Docker Desktop, then from the repository root run:

```powershell
docker compose up --build -d
docker compose ps
```

By default, the Compose database uses a local development password of
`postgres`. Override it by creating an untracked `.env` file:

```dotenv
POSTGRES_PASSWORD=choose-a-local-password
DOCKERHUB_NAMESPACE=varshith0087
```

The API reads the same `POSTGRES_PASSWORD` value. Compose publishes PostgreSQL
on port 5434 to avoid conflicting with a local PostgreSQL instance; the
containers communicate over the Compose network.

- Frontend: <http://localhost:5173>
- Backend API: <http://localhost:8081>
- Swagger UI: <http://localhost:8081/swagger-ui/index.html>
- Eureka dashboard: <http://localhost:8761>

The frontend's Nginx server forwards CRUD routes to the backend container.
Create a panel, verify it in the catalog, update it, and delete it from the UI.
The API also exposes `POST /Add`, `GET /DisplayAll`, `PUT /Update/{id}`, and
`DELETE /Delete/{id}`. IDs are generated by the database. Request validation
requires a panel model and manufacturer, positive integer wattage, and a
non-negative unit price.

Stop the stack with `docker compose down`; add `-v` only when intentionally
removing the persisted PostgreSQL data.

## Docker Hub publishing

The workflow builds:

- `varshith0087/docker-frontend-24000303631`
- `varshith0087/docker-backend-24000303631`

Before triggering the workflow, configure this repository secret in
**Settings → Secrets and variables → Actions**:

- `DOCKERHUB_TOKEN` — Docker Hub access token (never commit it to the repository).

Push to `main` or run **Build and publish Docker images** using
**Actions → Run workflow**. The workflow publishes both `latest` and
commit-SHA tags. Compose uses the same `latest` image names by default and
rebuilds locally when invoked with `--build`.
